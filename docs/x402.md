# Pay-per-scan with x402 (USDC on Solana)

AI agents can buy a Token Health Scan for **0.02 USDC** with no account and no API key. Payment uses the open [x402](https://x402.org) protocol (v2, `exact` scheme) on Solana. USDC only moves **after** the scan succeeds.

| | |
|---|---|
| HTTP endpoint | `GET https://qaqebpcqespvzbfwawlp.supabase.co/functions/v1/x402-scan?chain=solana&address=<token>` |
| MCP tool | `scan_token` on `https://qaqebpcqespvzbfwawlp.supabase.co/functions/v1/token-health-mcp` (free: `get_cached_scores`) |
| Public ledger | `GET https://qaqebpcqespvzbfwawlp.supabase.co/functions/v1/x402-ledger` |
| Chains scanned | Ethereum, BNB Chain, Base, Arbitrum, Polygon, Solana |
| Price / asset | 0.02 USDC, `EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v` on `solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp` |
| Facilitator | [PayAI](https://facilitator.payai.network) (pays the network fee, broadcasts) |

## Flow

1. Call the endpoint. The server answers `402` with a base64 `PAYMENT-REQUIRED` header (the `PaymentRequired` object: price, asset, payee, fee payer).
2. The client signs a USDC transfer and retries with a `PAYMENT-SIGNATURE` header.
3. The server asks the facilitator to **verify** the payment (read-only), **runs the scan**, then **settles**. If verification fails, the scan fails, or the scanner cannot verify enough data to give an overall score (HTTP `422`, partial data returned), nothing is settled and the payer is not charged.
4. The `200` response carries the verdict, a `PAYMENT-RESPONSE` header and a Solscan link to the settled transaction.

Every attempt is recorded in `public.x402_payments`. `payload_hash` is unique, so one signed payment buys one scan; a payment that never settled can be retried. Settled payments are public through `x402-ledger`, each with its transaction signature.

## Try it (Node)

```bash
cd examples/x402-agent-client && npm install
SOLANA_KEYPAIR_PATH=~/.config/solana/id.json node pay-scan.mjs solana JUPyiwrYJFskUPiHa7hkeR8VUtAeFoSYbKedZNsDvCN
```

The key stays in your process. The client SDK (`@x402/fetch`, `@x402/svm`) handles the 402 dance.

## MCP

`scan_token` follows the x402 MCP transport: a call without payment returns `isError: true` with the `PaymentRequired` in `structuredContent`; retry with the signed payment in `_meta["x402/payment"]`; the settlement receipt comes back in `_meta["x402/payment-response"]`. The official [`@x402/mcp`](https://www.npmjs.com/package/@x402/mcp) client does this automatically.

## Server configuration (Supabase secrets)

| Secret | Meaning | Default |
|---|---|---|
| `X402_PAYEE_SOLANA` | Wallet that receives the USDC. Its USDC token account must exist. | required |
| `X402_PRICE_USD` | Price per scan | `0.02` |
| `X402_NETWORK` | CAIP-2 network | Solana mainnet |
| `X402_FACILITATOR_URL` | Facilitator base URL | `https://facilitator.payai.network` |
| `X402_MEMO` | `1` puts `ths:<chain>:<token>` in the transaction memo | off |

Without `X402_PAYEE_SOLANA` the endpoint answers `503`. It never fakes a payment.
