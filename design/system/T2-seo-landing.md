## 1. Purpose & pages

SEO priority for the redesign sequence should follow impressions: comparison and guide pages first (191 combined impressions), then Solana, then Ethereum, then AI Agents (which reads more like an under-built stub than a mature pillar and may need a content pass before a design pass is worth it).

A note the blueprint's `discrepancies` field surfaces and this doc should not paper over: `token-sniffer-vs-tokenhealthscan` has a "legacy alias `/token-sniffer-comparison` which has no App.tsx route and no redirect" — a live 404/soft-error outside this doc's scope, but adjacent enough to flag to the AM.

## 2. Layout grid

### Current (measured across the 5 pages, 1440/768/375, dark)
Every T2 page shares the shared `Navbar`/`Footer` chrome (identical to T1 — same 65px sticky nav, same footer). Below the nav, all five wrap their content in a single centered column: `article.container` measured at **864px wide inside a 1440px viewport** (`max-w-*` + `mx-auto` + `px-*`), no sidebar, no shell border. At 18px body copy, 864px is roughly 55-60 characters per line for the guide/comparison prose — already narrower than raw viewport width but still wider than a tight reading measure, and some `p.text-lg` blocks run notably longer once list markup and inline `<strong>` tags are accounted for.

Section rhythm is uniform `section.mb-12` (48px bottom margin) — every section gets identical spacing regardless of content weight, no hairline rule between them, no background-color banding either (unlike T1, which at least alternates `bg-slate-800`). Pages are long: 4693-16314px tall at 1440. `TokenScanGuide` and `TokenSnifferComparison` embed one or more `img.w-full` hero/inline illustrations (feature photos, not data visuals) at up to 672×448.

### Target (foundation + T1 idiom, adapted for long-form)
`.shell` hairline border, same as T1. Content column narrows to **~68ch** (foundation-idiom target, not yet reference-validated) — at Archivo body 16px/1.55-1.6 that's roughly 620-680px, meaningfully tighter than the current 864px. Section breaks become `border-bottom: 1px solid var(--hair)` (the T1 `.blk` pattern) instead of bare margin — replaces the invisible `mb-12` seams with a visible rule, which also gives long pillar pages a scannable spine when skimmed. Every section gets a `.lab.eyebrow` mono label above its `h2` (T1 pattern, currently absent on all 5 T2 pages except the one inconsistent blue-label instance on Landing). Nested `h3`/`h4` subsections (Solana/Ethereum pillars run 3 levels deep) stay in the same column, no additional indentation rail — hierarchy is carried by type scale and the mono eyebrow convention, not by nesting chrome.

## 4. States

Only `default` element maps exist for all 5 T2 pages (blueprint has no T2 `loading` captures) — this matches reality: these are static content pages with no client-side data fetch gating first paint, so `loading`/`empty`/`error`/`gated` do not apply as page-level states. The one conditional worth naming: `AIAgents` has an "Admin-only UI section rendered conditionally via `useUserRole().isAdmin`" per site-blueprint's discrepancies field — this is an auth-gated *fragment*, not a page state, and the redesign should make sure that fragment is visually distinct (e.g. a `Surface-2` panel with a mono "ADMIN" tag) rather than blending into public content, since its presence/absence changes what a logged-out crawler and a logged-in admin each see.

## 5. Per-page deltas

- **`token-sniffer-vs-tokenhealthscan`** — the only T2 page with a true competitor-comparison structure (two named-competitor sections + feature table + verdict). Table styling is the highest-leverage single fix here (§3). Shortest of the content-heavy pages (6153px at 1440) — cheapest full redesign per impression earned.
- **`token-scan-guide`** — pillar/how-to hybrid. Has the confirmed transparent-H1 bug (§3) — fix this regardless of the broader redesign timeline, it's a visible defect today, not just a design-debt item. TLDR callout and the 5-pillar score breakdown (mirrors the actual scoring dimensions from T1's reference `.dc` grid) are natural anchors for hairline-cell treatment.
- **`solana-launchpads`** — deepest nesting (h2→h3→h4, "Comparative Deep Dive" with per-platform h4 subsections: Pump.fun, Letsbonk.fun, Believe App, MetaDAO, Devfun, Boop.fun) and longest page (16314px at 1440). No FAQ accordion confirmed in the heading sweep for this page specifically (unlike Ethereum) — verify before assuming the accordion fix applies here.
- **`ethereum-launchpads`** — same pillar pattern as Solana, one level less deep on average, has its own `EthereumFAQ.tsx` (accordion fix applies). Platform roster differs (DAO Maker, Poolz Finance, ChainGPT Pad, Seedify, Enjinstarter, Kommunitas, TrustPad, Spores) — content is chain-specific, layout pattern is shared with Solana, treat both pillar pages as one template with swapped content rather than two designs.
- **`ai-agents`** — thinnest page by far (4693px vs 6-16k for the others) and lowest impressions (1). Has the admin-conditional fragment (§4). Given the 1-impression signal and stub-like length relative to its siblings, flag to the AM whether this page needs a content expansion before the design pass — redesigning a 4693px stub to the same standard as a 16k-px pillar may not be the right sequencing call, but that's a content/SEO decision, not a design one, so this doc doesn't resolve it.

## 6. Migration notes

Same headline finding as T1: cross-referencing `component-inventory.json`'s `hardcodedColorOffenders` against every component imported by `AIAgents`, `EthereumLaunchpads`, `SolanaLaunchpads`, `TokenScanGuide`, `TokenSnifferComparison` (direct + one-level-deep) — **every single one reports `count: 0`.** None of the 9 offending files touch T2 at all. Combined with the T1 finding, this means **zero of the 91 hardcoded-color hits anywhere in the app live on a T1 or T2 page** — the entire offender list is scoped to scan-result/token-profile/agent-scan surfaces outside both docs' scope. Restyle-free by token flip for every shared component (`Navbar`, `Footer`, `ui/accordion`, `ui/badge`, `ui/button`, `ui/helmet`, `ui/skeleton`) and every page-specific section component listed in §1's imports.

What is **not** free, regardless of the clean color audit:
- **The transparent-H1 bug on `token-scan-guide`** is a real defect (measured, not inferred) that a token flip alone won't fix — the `bg-clip-text`/`text-transparent` pattern needs to be removed or given a proper gradient-fill fallback, independent of which theme is active.
- **The raw-hex icon colors** in `WhatIsTokenScanSection.tsx`'s 4-up grid and the emoji/raw-Tailwind-class list rows in `WhyTokenScanningMattersSection.tsx` are semantic colors expressed as literal Tailwind utility values rather than the app's CSS custom properties — they happen to already resemble the Score ramp conceptually (red=risk, green=good) but won't move when `.cobalt` lands because they're not wired to any token. This is the T2 equivalent of T1's LTD/LTDThankYou finding, at component scale rather than page scale: the inventory scan's "0 hardcoded colors" result is a floor on *tracked* components, not a guarantee that every visually-semantic color in the tree is token-driven. Confirm each flagged component visually under `.cobalt` before declaring it done.
- **Radix Accordion → native `<details>`** on 3 of 5 pages is a markup change, not a token change — budget it as such.
- **Column-width narrowing (864px → ~68ch)** touches every content section on all 5 pages simultaneously since it's a shared `article.container`/`max-w-*` change — do this once, centrally, rather than per-section, or the pages will drift out of sync with each other.

## 7. Verification checklist

Before any T2 page flips to `.cobalt`, the QA rig must show, at 375/768/1440, both `.cobalt` and `.cobalt.light`:

1. **Content column measures ~68ch**, not the current 864px-regardless-of-viewport pattern — verify via bbox width of the `article`/content wrapper at 1440 against the live body font size.
2. **Every section boundary has a visible hairline** replacing the current bare `mb-12` gap — screenshot diff should show a rule at each `section` transition on all 5 pages.
3. **Every H2 has a mono eyebrow above it** — spot-check at least 3 sections per page; today only one inconsistent instance exists across all of T2.
4. **`token-scan-guide`'s H1 renders visible text**, not `rgba(0,0,0,0)`, in both themes — this is a regression test for a confirmed live bug, not a new requirement.
5. **No emoji-as-icon remains** in list rows that sit alongside real SVG icons on the same page (confirmed present in `WhyTokenScanningMattersSection.tsx`) — grep rendered text nodes for emoji glyphs in icon-position slots.
6. **Semantic list/icon colors map to Score-ramp tokens**, not raw Tailwind hex — diff the computed `color`/`fill` against `--score-healthy`/`--score-risk`/`--score-critical` rather than eyeballing "looks about right."
7. **All 3 accordion-bearing pages** (`TokenSnifferComparison`, `EthereumLaunchpads`, `SolanaLaunchpads`) use native `<details>` with the reference's `+`/`−` summary marker and the `@supports (transition-behavior:allow-discrete)` open/close animation, killed under `prefers-reduced-motion`.
8. **Comparison table on `token-sniffer-vs-tokenhealthscan`** renders with `Surface-2` background, mono `th`, and the Token Health Scan column visually distinct in `Cobalt-hi` — matches the reference `.cmp` pattern exactly, not an approximation.
9. **Inline protocol/product-name mentions render in JetBrains Mono** across the Solana/Ethereum pillar pages — spot-check at least 5 platform-name instances per page (Pump.fun, DAO Maker, etc.).
10. **AI Agents admin-only fragment is visually gated** — confirm the conditional section (when rendered, as an admin) carries a distinct `Surface-2`/mono-tag treatment rather than blending into public content.
11. **Contrast floor** — same as T1 §7 item 11: no promoted body text sits on `Ink-3`; the current `Ink-2`-equivalent body copy (`rgb(148,163,184)`) throughout every T2 page's prose is the baseline to re-verify against the redesigned token, not assume unchanged.
12. **Reduced-motion kill-switch** verified across all animated elements introduced by the accordion and section-load treatments, matching the T1 reference's `@media (prefers-reduced-motion:reduce)` block.
